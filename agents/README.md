# Operating guide

Use these practices with ChatGPT Work for knowledge work and Codex for repository
work. Start with a real outcome, bounded access and a way to check the result.

| Guide | Purpose |
|---|---|
| [Quickstart](../ports/chatgpt/README.md) | Where to put instructions and run the first task |
| [AGENTS.md](../AGENTS.md) | Instructions for agents working in this repository |
| [Verification](VERIFICATION.md) | Evidence that the requested outcome was achieved |
| [Coordination](ORCHESTRATION.md) | Role selection, handoffs, shared state and delegation |
| [Skills and scheduling](SKILLS-AND-ROUTINES.md) | Make a tested workflow reusable, then recurring |
| [Prompts](PROMPTS.md) | Copyable task briefs |

For ChatGPT, use one complete prompt from [the role port](../ports/chatgpt/README.md).
For Codex, adopt the applicable repository rules in AGENTS.md and give the task
its role and acceptance criteria. Neither path installs connectors or launches
workers simply by saving a Markdown file.

The practices are adapted from the original stream material. Product claims
are tracked separately in [the product reference](../reference/PRODUCT.md).
