# ChatGPT playbooks

Nine adapted workflows. Each has source requirements, concrete steps, a trial
prompt, verification and a path to recurring work. Start with one outcome.

| Playbook | Outcome |
|---|---|
| [Engineering](engineering.md) | Turn a reported issue or approved specification into a verified pull request. |
| [Product Management](product-management.md) | Turn evidence into a testable product decision, specification and implementation handoff. |
| [Founders](founders.md) | Protect focus by combining customer preparation, product changes and market evidence into a short decision brief. |
| [Sales Engineering](sales-engineering.md) | Prepare a defensible technical answer, demo and sales material for a specific customer. |
| [Sales](sales.md) | Turn current account evidence into useful call preparation, tailored drafts and accurate CRM updates. |
| [Sales Development](sdr.md) | Produce a small, verified and ranked prospect batch with useful outreach drafts. |
| [Customer Support](customer-support.md) | Produce accurate support responses with evidence, escalation and separately authorized account actions. |
| [Post-Sales and Account Operations](post-sales.md) | Keep account plans and commitments current, with reviewable follow-ups after customer conversations. |
| [Marketing](marketing.md) | Carry a campaign from source-backed positioning to reviewed assets and an evidence-based experiment readout. |

Use [complete role prompts](../ports/chatgpt/README.md), explicit [handoffs](../ports/chatgpt/HANDOFF.md)
and [verification](../agents/VERIFICATION.md). Separate instructions, sources,
permissions and actual execution. These workflows do not promise automatic
agent-to-agent messaging or access to every connected application.

The [original revision](../PROVENANCE.md) preserves the Grok workshop narratives.
The active playbooks are adaptations, not claims that those demos ran in ChatGPT.
